# September 29: move the io_uring state machines into C#

[History index](README.md)

Following the epoll rewrite, the goal was to make the newer io_uring transports approachable as C# implementations rather than C engines behind a managed pipe adapter. The scope covered `IoUringTcp`, fd-bound `IoUringTls`, and layered `IoUringBio`; the older `io_uring` experiment and epoll were preserved unchanged.

## Ownership moved, not just the file names

`Engine.cs` now owns the dedicated thread, command drain, raw-CQE dispatch, accept/wake cancellation, connection IDs, page pools, and metrics. `RingConnection.cs` owns TCP and TLS progression, multishot terminal lifetimes, separate cancellation acknowledgments, partial send retry, linked final shutdown, and BIO ciphertext queues. Output-pipe completion and borrowed-send pinning remain in `Connection.cs`.

The native code is a liburing/OpenSSL ABI shim plus small BIO callbacks. It has no transport event dispatcher, connection list, or TLS scheduling loop. Main/BIO C sizes changed from 559/619 to 190/94 lines, approximately 76% less C overall.

Compared with epoll, completion ownership is the crucial extra requirement: requesting cancellation or receiving its acknowledgment does not release the original multishot operation. Socket and output-buffer disposal remain gated on original terminal CQEs. A partial linked send cancels its shutdown successor, and C# waits for that successor to drain before retrying. The tests reached those actual kernel paths.

BIO callbacks stay native but no longer own the transport. C# feeds their borrowed ciphertext page, observes consumption, recycles pages, and submits/drains ciphertext sends. The native output buffer remains stable until the final send CQE. There is no added memory-BIO staging copy.

## Same-session old/new comparison

The old deployment was preserved before editing. Two 15-second runs per cell reversed the configuration order, using the same original wrk2 client, four server cores, twelve client cores, 1,200 connections, 1,024-byte response, TLS settings, coalescing, and final-send batching.

| Transport/workload | Old C engine RPS | New C# engine RPS | Change |
|---|---:|---:|---:|
| IoUringTcp, TCP short | 74,949 | 76,120 | +1.6% |
| IoUringTcp, TCP long | 215,760 | 209,512 | -2.9% |
| IoUringTcp / SslStream, TLS short | 4,400 | 4,466 | +1.5% |
| IoUringTcp / SslStream, TLS long | 132,128 | 130,683 | -1.1% |
| Fd IoUringTls, TLS short | 8,179 | 7,781 | -4.9% |
| Fd IoUringTls, TLS long | 143,494 | 141,072 | -1.7% |
| Layered BIO, TCP short | 65,951 | 76,496 | +16.0% |

| Layered BIO, TLS short | 8,219 | 8,119 | -1.2% |
| Layered BIO, TLS long | 155,591 | 153,437 | -1.4% |

Fresh stock was 59,443 TCP short / 190,437 TCP long and 4,519 TLS short / 119,829 TLS long. The refactor kept the useful throughput advantages without a large persistent-I/O collapse, but this is not a zero-cost or zero-regression rewrite. Managed ownership, individual native calls, and changed allocation placement are tradeoffs; no profile attributes each percentage to one cause. Small-sample WSL drift remains material.

All 48 principal runs had complete ownership accounting. The required-kTLS follow-up produced 7,285 short / 134,602 long for the new engine, with both directions active on every completed handshake. The old short-kTLS process aborted during cleanup twice; those attempts are excluded, not averaged. Its old persistent mean was 133,103, roughly 1.1% below new.

## Checks and limitations retained

Real Kestrel fragmentation, persistent/pipelined/slow-reader traffic, complete response bodies, EOF, late TLS handshake rejection, idle-listener stop, and modes 0-3 final output were exercised across TCP, fd TLS, BIO TCP/TLS and kTLS. ASan/UBSan runs reached partial linked sends, canceled successor links, BIO partial ciphertext sends, and OpenSSL write retries. Epoll's unchanged rejection check remained a control.

The stricter OpenSSL close-notify probe over SslStream still failed on old raw transport, new raw transport, and stock alike; the refactor does not claim to fix that old boundary. Native fd/BIO TLS alerts were observed. A required-kTLS 4 MiB output check with diagnostic 4 KiB `SO_SNDBUF` stalled; the 32 KiB and normal-buffer checks passed with retries. The tiny-buffer case remains unresolved.

The implementation remains a non-shipping prototype. Fatal worker failures with live kernel ownership are process-fatal rather than releasing outstanding pins prematurely. Arbitrary ring failure recovery and exhaustive global pool exhaustion are not established.

The [managed io_uring report](../../IoUringTcp/README.md) has the current file map, complete tables, reproduction scripts, and local raw-evidence paths. Historical results are not rewritten to imply they measured this new engine.
